# اشتراک تجمیع‌شده MahsaFreeConfig

این بسته با GitHub Actions فایل‌های متنی پوشه‌های `app`، `mci` و `mtn` در مخزن `mahsanet/MahsaFreeConfig` را بررسی می‌کند و یک اشتراک واحد می‌سازد. فایل‌های جدید داخل این پوشه‌ها نیز خودکار پیدا می‌شوند.

## راه‌اندازی از طریق سایت گیت‌هاب

۱. وارد حساب خودت شو و در [ساخت مخزن جدید](https://github.com/new) یک مخزن **Public** بساز؛ مثلاً `mahsa-subscription`. گزینه **Add a README file** را فعال کن تا شاخه ساخته شود. نام شاخه باید `main` باشد.

۲. فایل ZIP را روی کامپیوتر Extract کن. داخل مخزن، **Add file → Upload files** را بزن و **محتویات پوشه بسته** را بارگذاری کن، سپس **Commit changes** را بزن. خود ZIP یا پوشه بیرونی `mahsa-subscription` را بارگذاری نکن؛ فایل `sources.json` باید در ریشه مخزن باشد.

۳. پوشه **`.github`** هم باید بارگذاری شود. بعد از بارگذاری، این مسیر را در مخزن بررسی کن:

```text
.github/workflows/update-subscription.yml
```

اگر `.github` در بارگذاری جا افتاد، **Add file → Create new file** را بزن، همین مسیر کامل را به عنوان نام فایل بنویس و متن فایل workflow داخل بسته را در آن کپی کن؛ سپس Commit کن.

۴. به تب **Actions** برو. اگر گیت‌هاب درخواست فعال‌سازی Actions داشت، فعال کن. workflow با نام **Update subscription** را باز کن، **Run workflow** را بزن و شاخه `main` را انتخاب کن. با سبز شدن اجرا، خروجی روی گیت‌هاب به‌روز شده است.

۵. لینک زیر را با نام حساب و مخزن خودت کامل کن و در قسمت **Subscription / افزودن اشتراک از URL** کلاینت وارد کن:

```text
https://raw.githubusercontent.com/YOUR_USERNAME/YOUR_REPOSITORY/main/subscriptions/all-base64.txt
```

نسخه متنی همان اشتراک نیز موجود است؛ برای کلاینتی که متن ساده می‌پذیرد:

```text
https://raw.githubusercontent.com/YOUR_USERNAME/YOUR_REPOSITORY/main/subscriptions/all.txt
```

برای ساخت لینک بدون تایپ دستی، داخل مخزن فایل `subscriptions/all-base64.txt` را باز کن و آدرس دکمه **Raw** را کپی کن. آدرس صفحه `github.com/.../blob/...` را به عنوان اشتراک وارد نکن.

## زمان به‌روزرسانی

- اجرا به صورت ساعتی در دقیقه ۱۷ هر ساعت به وقت UTC برنامه‌ریزی شده؛ اجرای GitHub Actions ممکن است با تأخیر انجام شود.
- اجرای دستی از تب Actions همیشه در دسترس است.
- تغییر `sources.json`، اسکریپت‌ها، آزمون‌ها یا workflow روی شاخه `main` نیز اجرا را آغاز می‌کند.
- لینک ثابت می‌ماند. برای دریافت محتوای تازه، داخل کلاینت **Update subscription** را بزن یا آپدیت خودکار کلاینت را فعال کن. گیت‌هاب و کلاینت ممکن است مدتی خروجی را کش کنند.
- اگر در مخزن عمومی ۶۰ روز هیچ فعالیتی نباشد، گیت‌هاب ممکن است اجرای زمان‌بندی‌شده را غیرفعال کند؛ از تب Actions دوباره آن را فعال کن. وقتی خروجی تغییر نمی‌کند، این بسته commit بی‌دلیل نمی‌سازد.

## چه چیزی وارد خروجی می‌شود؟

- لینک‌های کانفیگِ متنی یا فهرست Base64 که پروتکلشان در `sources.json` آمده است.
- موارد تکراری فقط وقتی حذف می‌شوند که تمام خط، شامل پارامترها و نام، دقیقاً یکسان باشد. پارامترهای اتصال و برچسب‌ها بازنویسی نمی‌شوند.
- فایل خالی در گزارش ثبت می‌شود و کانفیگی به خروجی اضافه نمی‌کند.
- فایل‌های فعلی `app/sub.txt` و `app/wireguard.txt` در بررسی اولیه بعد از Base64 به فهرست متنی قابل خواندن تبدیل نشدند؛ فعلاً با وضعیت `unsupported` گزارش می‌شوند و محتوایشان وارد خروجی نمی‌شود. این بسته ادعا نمی‌کند همه کانفیگ‌های اختصاصی برنامه مهسا را تبدیل می‌کند.
- اگر فایل جدید و قابل پشتیبانی به `app` اضافه شود، وارد خروجی می‌شود. `optionalFormatDirectories` در تنظیمات تعیین می‌کند کدام پوشه‌ها اجازه داشتن فرمت پشتیبانی‌نشده را دارند؛ پیش‌فرض فقط `app` است.
- اگر فایل `mci` یا `mtn` به فرمت ناشناخته تغییر کند، دریافت هر فایل با خطا روبه‌رو شود یا کل خروجی خالی شود، اجرا ناموفق می‌شود و نسخه منتشرشده قبلی حفظ می‌شود.
- این بسته کانفیگ‌ها را از نظر **اتصال، سرعت، امنیت تنظیمات یا سالم بودن سرور** آزمایش نمی‌کند؛ سازگاری هر پروتکل به کلاینت و نسخه آن وابسته است. خروجی YAML مخصوص Clash یا JSON مخصوص sing-box تولید نمی‌شود.

## تغییر منابع در آینده

فایل `sources.json` را در گیت‌هاب ویرایش و Commit کن. نام مالک، مخزن، شاخه، پوشه‌ها و فهرست پروتکل‌ها قابل تغییر است. ساختار فعلی برای یک مخزن منبع با چند پوشه طراحی شده است. فایل‌های `.txt` زیرپوشه‌ها هم بررسی می‌شوند.

محتوای فایل‌های فعلی، تنظیمات اتصال و شناسه‌ها در یک مخزن عمومی منتشر می‌شود؛ منابع پیش‌فرض هم عمومی‌اند. برای دریافت لینک Raw بدون ورود در کلاینت، مخزن خروجی را Public نگه دار.

## فایل‌های خروجی و بررسی اجرا

| فایل | کاربرد |
|---|---|
| `subscriptions/all-base64.txt` | لینک اصلی پیشنهادی برای اشتراک |
| `subscriptions/all.txt` | همان فهرست به صورت متن ساده |
| `subscriptions/report.json` | تعدادها، وضعیت هر فایل، هش محتوا و commit منبع |

در صفحه هر اجرای Actions، بخش Summary نتیجه همان اجرا و زمان بررسی را نشان می‌دهد. گزارش داخل مخزن به commit منبع اشاره می‌کند و زمانش هر بار بی‌دلیل عوض نمی‌شود. فایل‌های اشتراک داخل ZIP فقط نمونه واقعی زمان ساخت بسته‌اند؛ برای به‌روز ماندن باید workflow در حساب خودت اجرا شود.

## خطاهای رایج

- **workflow نمایش داده نمی‌شود:** مسیر `.github/workflows/update-subscription.yml` و شاخه `main` را بررسی کن؛ پوشه بیرونی بسته نباید در مسیر باشد.
- **خطای 403 هنگام push:** در **Settings → Actions → General → Workflow permissions** اجازه **Read and write permissions** را فعال کن، اگر تنظیمات حساب یا سازمان اجازه می‌دهد. workflow خودش فقط `contents: write` درخواست می‌کند. این بسته به توکن شخصی یا Secret جدید احتیاج ندارد.
- **push به خاطر تغییر هم‌زمان شاخه رد شد:** بعد از تمام شدن ویرایش‌ها، **Run workflow** را دوباره بزن. این workflow از force push استفاده نمی‌کند.
- **دریافت یا فرمت منبع خطا دارد:** جزئیات مرحله Generate subscription را بخوان؛ خروجی منتشرشده قبلی دست‌نخورده باقی می‌ماند.
- **کلاینت چیزی وارد نمی‌کند:** اول Raw بودن لینک و عمومی بودن مخزن را بررسی کن؛ بعد نسخه `all.txt` را امتحان کن. برای کلاینت‌هایی با فرمت اختصاصی، تبدیل جداگانه لازم است.

## اجرای محلی اختیاری

Node.js نسخه ۲۴ یا بالاتر لازم است؛ نصب پکیج اضافی لازم نیست:

```text
node --test

```
